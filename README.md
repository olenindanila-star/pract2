# Визуализатор графа зависимостей пакетов Rust (вариант 22)

Консольное (CLI) приложение на Python для анализа и визуализации графа
зависимостей пакетов менеджера пакетов Rust — **Cargo**.
Готовые менеджеры пакетов и сторонние библиотеки для получения
зависимостей не используются: только стандартная библиотека Python.

## Требования

- Python 3.8 или новее (Windows, Linux, macOS)
- сторонние библиотеки не нужны

## Запуск

Windows:

```
run.bat --package serde
```

Linux/macOS:

```
./run.sh --package serde
```

Или напрямую: `python src\main.py --package serde`.

## Тесты

```
python -m unittest discover -s tests
```

## Этап 1. Минимальный прототип с конфигурацией

Все настройки задаются **опциями командной строки**. При запуске
приложение выводит все параметры в формате `ключ = значение`.

### Параметры

| Опция | Описание | По умолчанию |
|---|---|---|
| `-p`, `--package` | имя анализируемого пакета (обязательно) | — |
| `-r`, `--repo` | URL-адрес репозитория или путь к файлу тестового репозитория | `https://index.crates.io` |
| `-m`, `--mode` | режим работы с репозиторием: `real` или `test` | `real` |
| `-o`, `--output` | имя файла с изображением графа (`.svg`) | `graph.svg` |
| `-a`, `--ascii-tree` | вывод зависимостей в виде ASCII-дерева: `yes` или `no` | `no` |
| `-f`, `--filter` | подстрока: пакеты, содержащие её, не анализируются | нет |
| `-h`, `--help` | справка | — |

### Обработка ошибок

| Параметр | Ошибка |
|---|---|
| `--package` | не задан; недопустимые символы; длиннее 64 символов; в режиме `test` — не большие латинские буквы |
| `--repo` | в режиме `real` — не URL (http/https); в режиме `test` — файл не найден |
| `--mode` | значение не `real` и не `test` |
| `--output` | расширение не `.svg`; пустое имя; папка не существует |
| `--ascii-tree` | значение не `yes` и не `no` |
| `--filter` | пустая подстрока или подстрока с пробелами |
| любой | неизвестная опция |

При ошибке выводится `Ошибка: ...` и программа завершается с кодом 1.

Демонстрация: `scripts\stage1_params.bat` (корректные запуски) и
`scripts\stage1_errors.bat` (ошибки для всех параметров).

### Пример

```
> run.bat -p tokio -m real -o tokio.svg -a yes -f test
package = tokio
repo = https://index.crates.io
mode = real
output = tokio.svg
ascii-tree = yes
filter = test

> run.bat -p serde -o graph.png
Ошибка: --output: файл должен иметь расширение .svg
```

## Этап 2. Сбор данных

Для заданного пакета Rust (Cargo) приложение получает **прямые
зависимости** из репозитория по URL-адресу (по умолчанию — индекс
реестра crates.io `https://index.crates.io`) и выводит их на экран.

### Как получаются данные

Менеджер пакетов Cargo хранит описание пакетов в индексе («sparse
index»). Для каждого пакета есть файл по адресу `<repo>/<путь>`:

| Длина имени | Путь | Пример |
|---|---|---|
| 1–2 символа | `1/<имя>`, `2/<имя>` | `2/cc` |
| 3 символа | `3/<первая буква>/<имя>` | `3/l/log` |
| 4 и больше | `<символы 1-2>/<символы 3-4>/<имя>` | `se/rd/serde` |

Каждая строка файла — JSON-описание одной версии пакета:

```json
{"name": "serde", "vers": "1.0.229", "yanked": false,
 "deps": [{"name": "serde_core", "req": "=1.0.229", "kind": "normal",
           "optional": false, "target": null}, ...]}
```

Алгоритм:

1. Файл скачивается модулем `urllib` (сторонние библиотеки не нужны).
2. Каждая строка разбирается модулем `json`.
3. Выбирается **последняя** версия: отозванные (`yanked`) пропускаются,
   обычные версии предпочитаются предварительным (`-beta`, `-rc`).
4. Из неё берутся **прямые зависимости**: обычные (`kind` = `normal`)
   и обязательные. Зависимости для тестов (`dev`), сборки (`build`) и
   необязательные (`optional`) не учитываются. У переименованных
   зависимостей берётся настоящее имя (поле `package`).
5. Если зависимость нужна только на определённой платформе (поле
   `target`), это показывается в выводе.

### Пример

```
> run.bat -p regex
Пакет: regex 1.13.1
Прямые зависимости (2):
  regex-automata ^0.4.16
  regex-syntax ^0.8.11
```

### Ошибки

| Ситуация | Сообщение |
|---|---|
| пакета нет в репозитории (HTTP 404) | `пакет '...' не найден в репозитории ...` |
| нет сети / неверный адрес | `не удалось подключиться к ...` |
| другая ошибка HTTP | `ошибка HTTP <код> при загрузке ...` |
| файл индекса повреждён | `неверный формат индекса (строка N)` |
| все версии отозваны | `у пакета нет доступных (не отозванных) версий` |

Демонстрация: `scripts\stage2_direct_deps.bat`.

## Этап 3. Основные операции

Строится **полный граф зависимостей** пакета — с учётом транзитивных
зависимостей (зависимостей зависимостей).

### Алгоритм: BFS без рекурсии

```
очередь = [исходный пакет], просмотрены = {исходный пакет}
пока очередь не пуста:
    пакет = взять из начала очереди
    зависимости = прямые зависимости пакета, кроме отфильтрованных
    граф[пакет] = зависимости
    для каждой зависимости, которая ещё не просмотрена:
        отметить просмотренной и добавить в конец очереди
```

- Очередь — `collections.deque`, рекурсии нет.
- **Фильтр** (`--filter`): пакеты, имя которых содержит подстроку, не
  анализируются и не попадают в граф.
- **Циклы** обрабатываются корректно: каждый пакет попадает в очередь
  один раз (множество просмотренных), поэтому обход всегда завершается.
  Найденные циклы выводятся (поиск в глубину с явным стеком, тоже без
  рекурсии): `Циклическая зависимость: A -> B -> C -> A`.

### Режим тестирования

С параметром `--mode test` вместо URL реестра указывается путь к файлу
описания графа (`--repo`). Пакеты называются большими латинскими буквами:

```
# комментарий
A: B C      # A зависит от B и C
B: D
C: D
D:          # у D нет зависимостей
```

| Файл в `examples/` | Что демонстрирует |
|---|---|
| `simple.txt` | граф без циклов, общая зависимость (ромб) |
| `cycle.txt` | цикл `A -> B -> C -> A` |
| `self_cycle.txt` | пакет зависит сам от себя |
| `complex.txt` | 13 пакетов, два цикла, недостижимый пакет `M` |
| `bad_name.txt` | ошибка: имя не из больших латинских букв |
| `bad_format.txt` | ошибка: строка без двоеточия |

### Пример

```
> run.bat -p A -m test -r examples\cycle.txt
Граф зависимостей пакета A
Репозиторий (тестовый): examples\cycle.txt
  A -> B
  B -> C
  C -> A, D
  D -> (нет зависимостей)
Пакетов: 4, связей: 4
Циклическая зависимость: A -> B -> C -> A
```

Демонстрация: `scripts\stage3_test_repo.bat` (тестовый репозиторий,
10 случаев) и `scripts\stage3_real.bat` (реальные пакеты).

## Структура проекта

| Путь | Назначение |
|---|---|
| `src/main.py` | точка входа |
| `src/config.py` | параметры командной строки и их проверка |
| `src/console.py` | настройка вывода UTF-8 (для Windows) |
| `src/cargo_index.py` | загрузка и разбор индекса реестра Cargo |
| `src/local_repo.py` | тестовый репозиторий из текстового файла |
| `src/graph.py` | построение графа (BFS) и поиск циклов |
| `tests/` | модульные тесты (`unittest`) |
| `examples/` | файлы тестовых репозиториев |
| `scripts/` | демонстрационные скрипты (`.bat`) |
| `run.bat`, `run.sh` | скрипты запуска |

## Функции

- `parse_config(argv)` — разбирает опции и проверяет каждую, возвращает
  `Config`; при ошибке бросает `ConfigError`.
- `validate_package`, `validate_repo`, `validate_mode`, `validate_output`,
  `validate_yes_no`, `validate_filter` — проверка отдельных параметров.
- `format_config(config)` — строки `ключ = значение` для вывода.
- `setup_console()` — включает UTF-8 для вывода в Windows.
- `index_path(name)` — путь к файлу пакета в индексе Cargo.
- `fetch_index(repo, name)` — скачивает файл индекса пакета.
- `parse_versions(text)` — разбирает строки JSON с версиями.
- `select_latest(versions)` — выбирает последнюю доступную версию.
- `direct_dependencies(version)` — извлекает прямые зависимости.
- `CargoRegistry` — источник зависимостей по URL, кэширует загрузки.
- `LocalRepository` — источник зависимостей из файла тестового
  репозитория; `parse_local_repo(text)` разбирает файл.
- `build_graph(root, source, exclude)` — граф зависимостей обходом BFS.
- `find_cycles(graph)` — циклические зависимости (DFS со стеком).
